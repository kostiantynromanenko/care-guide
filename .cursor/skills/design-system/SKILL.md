# Component Design System Skill

## Purpose

Use this skill after a visual direction is approved to build a small, consistent design system.

## Required token groups

Define and document:

- color tokens;
- typography scale;
- spacing scale;
- radii;
- border styles;
- shadow levels;
- container widths;
- breakpoints;
- motion principles;
- focus styles.

## Core component groups

### UI

- Button
- Link
- Badge
- Input
- Select
- Checkbox
- Radio
- Accordion
- Notice
- SectionHeading

### Content

- NeedCard
- CollectionCard
- RoutineCard
- ProductRecommendationCard
- ArticleCard
- RoutineStepper
- AffiliateCTA

### Layout

- Header
- MobileNavigation
- PageContainer
- Section
- Footer

## Rules

- Do not create a new visual style for every page.
- Use variants rather than duplicated components.
- Keep variants limited and purposeful.
- Do not add a component library without approval.
- Prefer CSS variables or Tailwind theme tokens.
- Keep component names technical and English.
- Keep all visible component text Ukrainian.
- Preserve clear hover, active, disabled, and focus states.

## Documentation

For each shared component document:

- purpose;
- variants;
- states;
- responsive behavior;
- content limits;
- accessibility notes.

## Approval boundary

The initial token set, typography, major card style, and primary button style require approval.
