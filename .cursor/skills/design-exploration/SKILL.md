# Design Exploration Skill

## Purpose

Use this skill when exploring a new visual direction before implementation.

## Required context

Read:

- `docs/PROJECT_CONTEXT.md`
- `docs/DESIGN_BRIEF.md`
- `docs/SITE_STRUCTURE.md`
- `docs/APPROVAL_WORKFLOW.md`
- `demo/demo-content.json`

## Goal

Create clearly differentiated design directions without silently choosing one.

## Process

1. Identify the page, section, or component being designed.
2. Preserve the approved information architecture.
3. Prepare 2–3 substantially different directions.
4. For each direction describe:
   - concept name;
   - visual idea;
   - palette;
   - typography;
   - layout;
   - card and button style;
   - image treatment;
   - mobile behavior;
   - strengths;
   - risks.
5. Recommend one direction, but do not implement it.
6. Stop and wait for explicit approval.

## Requirements

- Use Ukrainian for all public-facing demo copy.
- Keep the website project-centered rather than personality-centered.
- Do not imitate the official Hillary website.
- Do not make the project look like a traditional online shop.
- Do not introduce new pages or technologies without approval.
- Do not provide three superficial color variations of the same layout.

## Completion condition

This skill is complete only after the options have been presented and the agent has stopped for approval.
