# Responsive Design Skill

## Purpose

Use this skill whenever creating or reviewing responsive behavior.

## Primary rule

Design mobile first. The expected main traffic source is mobile.

## Required viewport checks

At minimum review:

- 360px;
- 390px;
- 768px;
- 1024px;
- 1440px.

## Mobile requirements

- no horizontal scrolling;
- comfortable tap targets;
- readable Ukrainian text;
- one-column layout where appropriate;
- concise card content;
- clear sticky or visible primary action when approved;
- mobile menu that is keyboard accessible;
- filters shown in a drawer or compact layout when necessary.

## Tablet and desktop requirements

- expand the mobile information architecture;
- do not invent a different desktop product;
- maintain readable line length;
- avoid excessive empty space;
- avoid overly dense grids;
- keep hero content balanced;
- preserve clear hierarchy.

## Ukrainian text considerations

Ukrainian labels may be longer than English equivalents.

The layout must tolerate:

- longer button labels;
- multi-line headings;
- validation messages;
- category names;
- disclosure text.

Do not solve long text by making fonts too small.

## Images

- use predictable aspect ratios;
- avoid important text inside images;
- prevent layout shift;
- preserve subject visibility on mobile crops.

## Review checklist

- navigation;
- hero;
- cards;
- routine steps;
- forms;
- filters;
- notices;
- footer;
- focus states;
- external CTA;
- text wrapping.

## Approval boundary

Major changes to mobile navigation, breakpoint strategy, or content order require approval.
